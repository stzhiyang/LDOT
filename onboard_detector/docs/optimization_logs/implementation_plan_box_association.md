# 修复Box关联成功率低的问题

## 问题描述

从日志可以看到数据关联成功率很低,经常出现:
- `o:0 +:9 -:9` - 9个框全部丢失,全部重新初始化
- `o:1 +:8 -:8` - 只有1个框成功关联
- 即使框数量相同也关联失败

## 问题根因

通过代码分析,发现以下问题:

### 1. **核心问题:使用历史bbox而非预测bbox计算代价**
在`boxAssociation`函数中(1336行),计算尺寸差异和点云标准差差异时,使用的是**历史轨迹的旧状态**:
```cpp
const onboardDetector::box3D &histBox = this->boxHist_[j][0];
const Eigen::Vector3d &histStd = this->pcStdHist_[j][0];
```
这是错误的!卡尔曼滤波已经预测了新的位置,但是尺寸和标准差仍然使用旧值,导致不一致。

### 2. **点云标准差权重过高**
- 位置权重: 0.7 (马氏距离,最可靠)
- 尺寸权重: 0.2
- 标准差权重: **0.5** (过高!)

点云标准差在同一物体的不同帧之间变化很大(扫描角度、遮挡、点云密度等因素),不应该有这么高的权重。

### 3. **检测bbox尺寸不稳定**
激光雷达检测的bbox尺寸每帧都会波动,即使是同一物体,尺寸差异也可能很大,导致尺寸代价很高。

### 4. **关联门限可能过严**
- 3D门限: 11.345 (卡方分布,自由度3,99%置信度)
- 2D门限: 9.21 (卡方分布,自由度2,99%置信度)

在卡尔曼滤波刚初始化或协方差较大时,即使是正确的匹配也可能被拒绝。

## 解决方案

### 修改1: 使用预测位置的协方差计算代价

**位置**: `dynamicDetector.cpp` 第1330-1410行

**改动**: 在关联代价计算中传递预测的bbox(而非历史bbox):

**理由**: 应该基于预测状态(而非历史状态)进行匹配判断,保持一致性。

### 修改2: 调整代价函数权重

**位置**: `detector_param.yaml`

**改动**:
```yaml
association_pos_cost_weight: 1.0    # 提高位置权重(马氏距离最可靠)
association_size_cost_weight: 0.15  # 降低尺寸权重(检测不稳定)
association_std_cost_weight: 0.1    # 大幅降低标准差权重(变化大,不可靠)
```

**理由**: 
- 马氏距离已经考虑了卡尔曼滤波的不确定性,是最可靠的指标
- 尺寸和点云标准差容易受检测波动影响,应降低权重

### 修改3: 放宽关联门限

**位置**: `dynamicDetector.cpp` 第1391和1403行

**改动**:
- 3D门限: 11.345 → **16.0** (约99.9%置信度,更宽松)
- 2D门限: 9.21 → **13.0** (更宽松)

或者使用自适应门限:根据协方差行列式大小动态调整。

**理由**: 在轨迹初期或快速运动时,协方差较大,需要更宽松的门限。

### 修改4: 添加调试输出(可选)

添加更详细的关联代价输出,便于调试:
- 输出每个匹配对的代价分解(位置/尺寸/标准差)
- 输出被门限拒绝的匹配
- 输出协方差矩阵的行列式(反映不确定性)
